## 关键决策

- 当前资料边界：只读取并使用 `docs/plans/CURRENT.md` 和 `docs/需求澄清问题清单.md`；其余文件当前均不作为准确需求依据。
- 需求同步流程：先完成模糊点审核与甲方确认，再同步更新两份指定文件，通过独立 GitHub PR 提交到 `main` 分支并自动合并；不设置 PR 后置审核环节。
- 原始需求文件只作为输入依据，不直接修改。
- 模糊点整理文件采用 Markdown，便于后续逐条补充甲方结论。
- 每个关键问题都保留“建议口径 / 甲方结论 / 开发影响”。
- 看板层级采用：主管 → 组长 / 小组 → 平台。
- 主管端初始页面：渠道总览页 + 私域组展示页 + 达人组展示页 + 分销组展示页。
- 私域组展示页、达人组展示页、分销组展示页是页面集合 / 容器，内部包含组别分析页 + 客户列表页 + 客户详情页。
- 主管可以查看各组数据，包括各组展示页集合内的组别分析、客户列表、客户详情数据，但主管只负责查看，不负责管理小组。
- 组长端页面：自己所属组的展示页集合。
- 主管端和组长端使用不同页面集合。
- 组长端管理自己的小组，只能访问自己所属组，没有权限查看其他组页面或其他组数据。
- 主管和组长在各自权限范围内全部字段可见，暂不做字段级权限差异。
- 业务负责人维度暂定保留，但必须作为可选维度设计，不能强绑定核心页面和核心指标。
- 第一版采用普通网页端账号登录 / 系统账号分发。
- 三个组展示页不重复开发，开发层可以复用布局和基础组件；但复用不得改变 `项目框架.txt` 中写明的页面展示模块。
- 销售金额展示周期固定为：昨日、近7日、近30日、自定义时间。
- 客户指标固定周期需要包含：昨日、近7日、近30日；每个周期展示客户总数、有拿货客户数、未拿货客户数、活跃客户数、沉默客户数，并覆盖整体、各组、各平台维度。
- 健康度模块固定展示昨日、近7日、近30日、自定义时间；每个周期展示健康客户数、观察客户数、风险客户数、流失预警客户数，并覆盖整体、各组、各平台维度。
- 待跟进提醒模块固定展示昨日、近7日、近30日、自定义时间；每个周期展示待跟进客户数量、重点风险客户数量、异常下滑客户数量，并覆盖整体、各组、各平台维度。
- 不同平台原始销售数据需要先清洗成统一的 `sales_date` 和 `sales_amount`，平台差异放在数据清洗 / 指标计算层，不放在页面组件里。
